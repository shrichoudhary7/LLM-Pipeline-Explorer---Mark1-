Tokenizer & Subword Vocabulary

Converting raw text strings into discrete integer IDs using subword segmentation.

String → Token IDs [int]

Why Subwords? (The CS Tradeoff)

Character-level keeps vocabulary tiny (~100) but makes sequences huge—and since Attention costs O(L²), long sequences explode compute. Word-level fails on unseen words (OOV), plurals, and code identifiers.

Modern LLMs use Subword Tokenizers (WordPiece in BERT, BPE in GPT-4/Llama): frequent words stay single tokens, while rare words split into known pieces (dogs → dog + ##s).

Compression & Vocabulary Tradeoff
Encode: text ──▶ [t₁, t₂, ..., t_L], tᵢ ∈ {0, ..., |V|-1}
Ratio : chars_per_token = len(text) / L
GPT-4 : |V| ≈ 100,277 (cl100k_base BPE)
Llama3: |V| = 128,256 (tiktoken BPE)

CS Deep Dive: WordPiece vs. BPE & Byte-Level Fallback

WordPiece (used in BERT) scans an unknown word left-to-right and greedily takes the longest matching prefix in the vocabulary, marking continuation pieces with ##. If a character isn't in the vocabulary, the word falls back to [UNK].

Byte-Pair Encoding (BPE) (used in GPT-2/3/4, Llama, Claude) starts with individual characters (or UTF-8 bytes so [UNK] is impossible!) and iteratively merges the most frequent adjacent pair of tokens until reaching target vocabulary size |V|. Notice how shrinking the slider directly increases sequence length L, which increases downstream attention cost quadratically (O(L²)).

Token Embeddings (Lookup Matrix E)

Mapping meaningless integer IDs to dense, continuous semantic vectors in ℝᵈ.

int[L] → Matrix X ∈ ℝ^(L × d)

Why Not Feed Token IDs Directly Into a Neural Net?

Token IDs are arbitrary hash keys: just because cat = 4 and dog = 5 doesn't mean cat + dog = 9. Instead, an LLM learns a giant weight matrix E of shape (|V| × d_model).

Fetching a token's embedding is mathematically equivalent to multiplying a one-hot vector by E, and in code it's simply an O(1) array row lookup: vector = E[token_id].

Embedding Matrix Lookup
e_i = one_hot(id_i) · E = E[id_i, :] ∈ ℝᵈ
GPT-3 : |V|=50,257 × d=12,288 ≈ 617M params
Here : d = 20 interpretable semantic dimensions
L2 Norm: ‖e‖₂ = √(∑ eⱼ²)

03

Vectors, Cosine Similarity & 3D Embedding Space

Measuring semantic similarity via angles, comparing Lexical vs. Semantic vectors, and projecting high-D space to 3D via PCA.

ℝᵈ Vectors → cos(θ) & 3D PCA

Why Cosine Similarity Beats Euclidean Distance in LLMs

Two texts about the same topic (one short, one long) can have different vector magnitudes, giving a large Euclidean distance ‖A − B‖₂. Cosine Similarity measures only the angle θ between vectors: +1.0 means identical direction, 0.0 means orthogonal (unrelated), and −1.0 means opposite.

Since humans can't visualize 20D or 4,096D space, we use PCA (Principal Component Analysis) to find the top 3 orthogonal directions of maximum variance (PC1, PC2, PC3).

Similarity Metrics & PCA Projection
Dot Product : A · B = ∑ Aᵢ Bᵢ = ‖A‖ ‖B‖ cos(θ)
Cosine Sim : cos(θ) = (A · B) / (‖A‖₂ · ‖B‖₂)
L2 Distance : d(A,B) = √(∑ (Aᵢ − Bᵢ)²)
PCA 3D : Z = (X − μ) · [v₁, v₂, v₃] (top-3 eigenvecs of Cov)

04

Positional Encoding (Injecting Word Order)

Transformers process all tokens in parallel—without positional signals, "Dog bites man" equals "Man bites dog".

E(tok) + PE(pos) → X₀ ∈ ℝ^(L × d)

Sinusoidal Waves as a Binary Clock

In the original Transformer (Vaswani et al., 2017), each position pos gets a unique fingerprint made of sine and cosine waves across dimensions: low dimensions oscillate rapidly (fine local distance), high dimensions oscillate slowly (long-range order).

Adding PE(pos) directly to the token embedding lets attention layers linearly compute relative offsets (pos + k). Modern LLMs (Llama, Gemma, Qwen) refine this into RoPE (rotating Q/K vectors by angle pos · θᵢ).

Sinusoidal Positional Encoding
PE(pos, 2i) = sin( pos / 10000^(2i / d) )
PE(pos, 2i+1) = cos( pos / 10000^(2i / d) )
Model Input : X[pos] = E[token_id] + PE(pos)

05

Self-Attention Mechanism (Q, K, V & Causal Mask)

How every token dynamically gathers context from other tokens to resolve meaning (e.g., what does "it" or "bank" refer to?).

X ∈ ℝ^(L×d) → Context-Aware Z ∈ ℝ^(L×d)

The Database Lookup Analogy (Query, Key, Value)

Every token vector xᵢ is linearly projected into three roles: Query (Q) = "What context am I searching for?", Key (K) = "What label do I advertise?", Value (V) = "What payload do I contribute if attended to?".

Dividing by √d_k keeps dot products from growing too large (which would push softmax into vanishing-gradient plateaus). In decoder LLMs (GPT/Llama), a Causal Mask sets future positions to −∞ so token t can only attend to ≤ t.

Scaled Dot-Product Multi-Head Attention
Q = X·W_Q, K = X·W_K, V = X·W_V
Scores = (Q · Kᵀ) / √d_k + Mask
Weights = softmax(Scores, axis=-1) // rows sum to 1
Output = Weights · V // Complexity: O(L² · d)

Logits, Softmax & Autoregressive Sampling

Turning the final hidden vector into a probability distribution over the entire vocabulary—and picking the next token.

h_T ∈ ℝᵈ → P(next | context) → Append & Loop ↻

How Temperature, Top-K & Top-P Control Generation

The final layer multiplies the last token's hidden state by the unembedding matrix to produce raw scores called logits (z ∈ ℝ^|V|). Dividing by Temperature T before Softmax reshapes entropy: T → 0 approaches deterministic greedy decoding; T > 1 flattens probabilities for higher creativity/randomness.

Top-K keeps only the k most probable tokens; Top-P (Nucleus) keeps the smallest set of top tokens whose cumulative probability reaches p. The sampled token is appended to the prompt and the whole pipeline repeats!

Temperature-Scaled Softmax & Shannon Entropy
P(wᵢ) = exp(zᵢ / T) / ∑ⱼ exp(zⱼ / T)
Entropy H(P) = − ∑ P(wᵢ) · log₂ P(wᵢ) (bits)
Loop : prompt ← prompt + [sampled_token]
